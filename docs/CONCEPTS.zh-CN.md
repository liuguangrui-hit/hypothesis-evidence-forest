# 动态假设-证据森林

这个系统只有一个核心设计，其余都是它的推论：**假设是全局实体，不属于任何一个课题。**

传统的做法是一个课题一棵树，树与树之间互不相通。于是同一条假设会在三个课题里被验证三遍，
某次实验推翻了它，另外两个课题还在继续往下跑。这个系统把所有课题的假设放进同一片森林：
树是课题各自的论证结构，节点指向的假设是共享的。

---

## 1. 森林的构成

```
idea（课题）          一棵树，代表一条论证路线
  └─ node（节点）     树里的一个位置：k=1.2.1、parent、role
       └─ hyp        节点指向的假设 —— 全局唯一，可被多棵树同时指向
```

三者的关系是：**树拥有节点，节点引用假设，假设不属于任何树。**

同一条假设 `H-02` 可以：

| 在哪棵树 | 处在什么位置 | 这棵树怎么用它 |
| --- | --- | --- |
| P-014 | 第 2 层中间节点 | 本课题自证，向上支撑父节点 |
| P-016 | 根前提 | 直接采纳，不再往下拆，是整条论证的出发点 |
| P-017 | 已证叶子 | 作为已验证前提引用，无需重跑实验 |

位置由**各棵树自己的论证结构**决定，不是假设的属性。这一点是后面所有行为的来源。

### 角色（role）

每个节点标记它打算怎么对待这条假设：

- `own_to_prove` —— 本课题要自己证明它，会继续往下拆分子假设；
- `borrowed_assumption` —— 借用前提，直接采纳，不再展开。

同一条假设在 A 树里是 `own_to_prove`，在 B 树里可以是 `borrowed_assumption`。

## 2. 证据是带符号的增量

每次实验结束，往**假设**（而不是往树）写一条证据：

```json
{ "exp": "e_15", "idea": "P-014", "delta": 0.6, "note": "七档拟合 R²=0.98", "at": "..." }
```

- `delta` 有正负。累加得到该假设的**累积分数**。
- `idea` 记录这条证据是在哪个课题下跑出来的 —— 证据有来源，但不归属。
- 累积 ≥ **+1.0** 转 `self_verified`；≤ **−1.0**，或连续三次 `PIVOT` 无改善，升级到裁定队列。

**一次写入，所有引用方同时更新。** 这是共享假设最直接的收益：三个课题共用的 baseline 重测一次，
三边的下游节点一起解冻，不必各跑一遍。

### 状态不是手填的

界面上看到的状态是**算出来的**，不是存的：

```
有实验在跑            → testing
被提交裁定            → pending_review
累积 ≥ +1.0           → self_verified
有证据但未到阈值      → active
什么都没有            → untested
```

这样就不会出现「状态写着已验证、证据却是负的」这种自相矛盾。

## 3. frontier：现在能跑什么

frontier 是全局的「依赖已就绪、可以直接开跑」的假设集合。一条假设进入 frontier 需要同时满足：

1. 它的 `depends_on` 全部 `self_verified`；
2. 没有实验正在它上面跑，也没有排队中的；
3. 所在节点没有被裁定冻结；
4. 它本身还没结清（已自证且不需要复跑的不再出现）；
5. **它在至少一棵树里是叶子** —— 有子节点的主张由子节点结清，不直接跑实验。

frontier 跨全部课题排序，优先服务多个课题的假设。这让调度回答一个具体问题：
*手上这一个空闲槽位，跑哪条假设收益最大？*

## 4. 裁定：同一个失效，三种后果

当证据互相矛盾、或连续三次换方法都没有改善时，executor **停止在这条假设上继续展开**，
交给人。这是系统唯一会停下来等人的地方。

裁定要回答的不是「它对不对」，而是「判它不成立，各个课题各自会怎样」：

| 它在该树里的位置 | 后果 | 影响范围 |
| --- | --- | --- |
| 根前提 | 整棵树的节点回到 `untested`，已写的章节要重写 | **global** |
| 中间节点 | 冻结其下游子树，相关排队实验撤下 | **branch** |
| 叶子，且本课题有独立正证据 | 不受影响 | **local** |

四种裁定结果：

- `close` —— 判定不成立并关闭，按上表传播冻结；
- `return_active` —— 证据不足以判定，附新方向退回 frontier；
- `narrow_scope` —— 改写 claim 缩小适用范围后重开（保留正证据，丢弃范围外的负证据）；
- `downgrade` —— 降级为借用前提，标注未验证。

**裁定只写 `verdicts/<hyp>.json`，节点状态由裁定派生。** reviewer 不直接改树。
责任边界清楚：谁写哪个文件是固定的，出了问题能追到人（或 agent）。

## 5. 三个 agent 的写入边界

| agent | 只写 | 不能碰 |
| --- | --- | --- |
| surveyor | `index.jsonl`、`sources/`、游标 `state.json` | 假设树、裁定 |
| executor | `events.jsonl`、`artifacts/`、实验记录 | `tree.json` 里的状态、裁定 |
| reviewer | `verdicts/` | 树结构、实验产物 |
| 人 | 裁定、排队、立项批准 | —— |

边界是刻意设计的：没有任何一方能同时制造证据又判定证据。

---

## 6. 实验树：一条假设怎么被跑出来

假设树回答「要证明什么」，实验树回答「怎么试出来的」，分四个阶段：

```
初探 probe   →  调参 tune  →  主实验 main  →  消融 ablate
```

- 节点类型分**新写 / 修错 / 改进**，失败节点**不删**，留着避免重蹈覆辙；
- 只有被标成「代表节点」的结果才写回假设树，其余留在实验树里做记录；
- 一整张 batch × seed 扫描矩阵，最终**只产生一条证据** —— 写回去的是「趋势成立、相邻档不可分」
  这一句话，不是 18 个数字。

---

## 7. 写作是证据的另一种视图

章节由假设树映射：节点状态一变，对应小节自动标记待更新。

- 每一句断言都要能指回它的假设和实验 id；
- 扫描会挑出「任何 / 普遍 / 始终」这类词，回去核对证据里的**适用范围**；
- 还有「过度声称」没改完时，导出投稿版的按钮会停下并列出是哪几条。

写作发现的缺口（某段只有单次运行支撑）直接回到实验队列，形成闭环。

---

## 8. 人在什么位置

系统不替人决定三件事：

1. **给方向** —— 来源白名单、topics、是否立项；
2. **裁定假设** —— 证据矛盾时的取舍；
3. **拍板投稿** —— 什么时候算写完了。

其余部分——采集、分级、归纳、排实验、剪枝、重试、画图、查主张——系统自己做完，
每一步记进 `events.jsonl`。
